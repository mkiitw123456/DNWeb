# DNWeb

繁體中文公會管理網站，React + Vite 前端、Node API。本機使用 JSON，Vercel 使用 Firebase Firestore。

## 目前介面與資料維護

- 大廳為精簡歡迎列、積分摘要與每日活動；「我的冒險」僅呈現摘要，不再提供個人逐筆歷史。活動設定與報表移至「管理後台 → 活動管理」。
- 明細帳本保留最近 35 天，以有效登入讀取觸發背景清理（每小時至多一輪）；個人歷史的重複副本會移除。累積／每週積分及參與次數獨立儲存，不因明細清理而減少。既有與新提交的每日收據也會清理過期資料；管理員調分收據保留以避免重複調分。
- 管理員可刪除一般帳號；主要管理員可刪除其他管理員。不能刪除自己或主要管理員，需輸入完整帳號名稱確認。先移除登入資格，再清理活動集合；中斷的工作記於 `pendingUserDeletions`，可由後台重試。涉及其他人的分帳僅匿名處理，保留他人的金額。
- 本次包含一次性移除指定測試帳號的遷移，同時比對固定帳號 ID 與 `QA_Deploy_20261116` 名稱，不會刪除其他或未來同名帳號。遷移完成旗標為 `deploymentTestCleanupV1`。
- 首次登入先提供 Discord ID 設定（可略過），再顯示聚焦導覽；完成狀態存於既有帳號。側欄可重開。
- 外觀設定提供背景、卡片、側欄、外框、重點／按鈕顏色與背景漸層；按帳號 ID 存於瀏覽器 localStorage，不寫入 Firebase。切換動畫遵守 `prefers-reduced-motion`。

### Discord 成員與三種通知

`DISCORD_BOT_TOKEN` 與 `DISCORD_GUILD_ID` 必須設定於 Vercel 伺服器環境；Bot 須加入指定伺服器，並在 Discord Developer Portal 的 Bot 設定開啟 **Server Members Intent**。伺服器會分頁取得成員清單、短暫快取 5 分鐘，再進行不分大小寫的任意位置比對，因此 `Wo` 與 `lf` 都能找到 `MrAirWolf`。最多處理 20,000 位成員，超過時提示手動填 ID；不回傳 Token，也不讀取聊天訊息。

一般成員選取／輸入的 ID 只會寫入 `discordPendingId`。管理員核對後按「確認 Discord 申請」才寫入正式 `discordId`，避免透過暱稱搜尋冒認他人的結算等權限。尚未設定 Bot 時仍可手動輸入或略過。自動驗證本人需另做 Discord OAuth，此版本採管理員確認。

「管理後台 → Discord 通知」提供三組獨立 Webhook：Log（成功登入／登出、活動、資料變更）、重大通知（註冊及管理員變更）、出團通知（保留）。瀏覽／輪詢不發通知，密碼、Token 與 Webhook 不入訊息；通知狀態保留最近 30 筆及 24 小時內進行中的工作，只顯示少量失敗重試。既有 Log／出團網址不變，重大通知需要另外填入目標頻道 Webhook。

以下為第一階段與歷史功能的設計背景；目前介面及保存政策以上方說明為準。

## 活動大廳（第一階段）

登入或註冊後預設進入「冒險大廳」。提供每日抽籤、快問快答、隨機事件、遊戲暱稱、個人歷史與本週榜單。沿用既有帳號 ID，不以暱稱辨識身分，多角色不會重複領分。

- 活動採 `Asia/Taipei`，每日 09:00 重置參與次數、週一 00:00 開始新週；角色副本仍維持原本週六 09:00 重置。
- 預設每種活動每日一次、參與 5 分，快問快答答對另加 2 分。可於「冒險大廳 → 活動管理」修改每日上限、分數、開關、名稱、說明、題庫與 Discord 連結。
- 每筆提交使用唯一識別碼，後端在 transaction 內驗證日期、規則版本、次數與答案；重送同一筆只計分一次。答案不會事先提供給一般成員。
- 管理員可查詢日期區間、成員摘要、活動次數與明細，匯出 CSV，以及輸入理由調整積分。調整保留操作者、前後分數，不增加參與次數。報表最多 366 天／5,000 筆，超過時明確要求縮小範圍，不截斷匯出。
- 個人歷史每頁 50 筆；榜單最多顯示 50 位使用中成員。暱稱可重複，但帳號與紀錄獨立。
- 首次恢復登入合併大廳資料為一個請求，並延後載入角色、管理與排班頁面的程式。網路暫時中斷時提供重試，不要求重新輸入帳密。不要變更正式站的 `SESSION_SECRET`，否則既有 Cookie 將失效。
- 「出團排班」仍隱藏；`src/App.jsx` 的 `SHOW_RAID_SCHEDULING` 可恢復入口，排班程式與資料保留。現在角色資料僅本人可見，群組功能已停用；下方較早的群組／懸賞說明屬於歷史版本。

活動資料使用同一 Firebase 專案的 `guild_activity` 集合，與既有 `dnweb/state` 分離。包含 `config`、`config/versions/vN`、`member_<id>`、`day_<hash>`、`week_<日期>`、`receipt_<hash>` 文件，明細分別在 `guild_activity/records/ledger` 與 `guild_activity/member_<id>/history` 子集合。所有讀寫透過後端 Admin SDK，前端沒有 Firebase 憑證；歷史查詢僅使用 `createdAt` 的預設單欄位索引。沿用現有 `FIREBASE_SERVICE_ACCOUNT_JSON`，不需要建立新 Firebase 專案或清除資料。首次參與／儲存時自動建立新文件。

本機活動資料另存於 `.local/activities.json`（或 `LOCAL_DATA_DIR`）。備份與移轉時須一起保留活動集合／此檔案；既有帳號整理的 `dnweb/state` 備份不包含活動紀錄。網站不讀取 Discord 訊息，第一階段只提供公會連結；稱號、共同目標及 Discord Bot 互動屬於後續階段。

## 本機啟動

需要 Node.js 22.12 以上。

```powershell
cd D:\DNWeb
npm ci
Copy-Item .env.example .env
# 編輯 .env，設定 INITIAL_ADMIN_PASSWORD 與 SESSION_SECRET
npm run dev
```

開啟 http://127.0.0.1:5173 。全新資料庫的初始管理員為 `MrAirWolf`，密碼來自 `INITIAL_ADMIN_PASSWORD`。既有資料庫不會依名稱自動提升權限或變更密碼。

## 帳號與登入

登入頁可自行註冊帳號及密碼，完成後立即登入，新帳號固定為一般成員。帳號不分大小寫、最多 30 字；密碼最多 128 字，使用 scrypt 雜湊。

登入使用 HttpOnly / SameSite=Lax Cookie，正式站加上 Secure。伺服器不設定新登入的到期時間；Cookie 為 400 天並隨有效請求續期。主動登出、瀏覽器移除 Cookie、管理員停用帳號或重設密碼後需要重新登入。

## 角色、職業與副本

- 一般成員只能取得自己與同群組的角色資料，權限由伺服器過濾。未加入群組時只看自己；管理員可看所有成員、角色與群組。
- 僅本人及管理員可編輯角色，同組可查看但不可代改。
- 角色有名稱、血量、攻擊力與職業；疲勞欄位與每日恢復機制已移除。舊資料讀取時自動移除疲勞欄位。
- 每個副本可輸入已完成次數，或按「全完成」直接填入伺服器設定的上限。
- 台灣時間每週六 09:00 重置副本次數。讀取時補算，前端每 30 秒及切回視窗更新。
- 職業預設為劍聖、傭兵、箭神、遊俠、元素使、魔導士、賢者、祭司、物蘿、魔蘿，使用 `public/icons/` 的 55×55 PNG。滑鼠停留或鍵盤聚焦顯示中文名稱。
- `shared/professions.js` 是中英文及圖示對照表。舊有同名中文／英文職業會保留 ID 並補上圖示；其他自訂職業仍保留，可由管理員指定圖示。

## 群組

每人可建立、加入多個群組，沒有單一群組限制。可建立群組，建立者輸入對方的登入帳號送出邀請。伺服器檢查帳號是否存在、啟用，以及是否已在該目標群組內。

邀請會顯示於登入後各頁上方，對方可接受或取消。接受邀請只處理該筆邀請，保留其他群組邀請。已送出邀請可在建立者的群組面板看到。

建立者可踢出成員；成員可自行退出指定群組，其他群組不受影響。建立者退出時會先確認，再解散群組並清除邀請；不刪除任何角色。角色頁可依群組篩選；一般成員可見所有共同群組成員的聯集，並不會沿著其他人的群組繼續擴大權限。管理員可在角色頁查看所有群組。

## 懸賞

所有已登入成員都可看見全部懸賞，不受群組限制，也不要求發布者當下在線。可依副本關卡篩選、新增自訂名稱的懸賞。選擇分類後新增會預選該關卡。本人及管理員可編輯或刪除。仍有懸賞的關卡不可直接刪除，需先移動或刪除懸賞。

交易所、結算已從導覽及畫面移除；舊交易資料與後端程式暫時保留，方便未來恢復。一般成員的頁面資料不再附帶交易及結算。

## 正式資料的一次性帳號整理

部署此版本後，以既有管理員登入「管理後台 → 一次性帳號整理」，確認後：

1. 確認資料庫有已啟用的 `MrAirWolf`；若沒有則停止，不刪除資料。
2. 先備份整理前的完整資料，再提升現有 MrAirWolf 為管理員。
3. 刪除 Wolf、shomen、Avalon、Ricky 的帳號、角色、懸賞、所建群組與交易，移除群組成員與邀請參照。
4. 其他使用者擁有的歷史結算保留原金額，刪除帳號的分帳欄位改為匿名，避免破壞其他人的金額紀錄。
5. 記錄已完成標記，避免重複執行。若執行者本身被刪除，立即清除登入 Cookie。

Firebase 備份位於 `dnweb_backups/before-account-cleanup-...`，與資料修改在同一 Firestore transaction 內提交。本機備份在 `.local/before-account-cleanup-....json`。備份含密碼雜湊等敏感資料，勿提交 Git。此功能只允許已登入管理員操作，不會因公開註冊使用了指定名稱就提升權限。

## 部署與資料

Vercel：Framework Vite、Build `npm run build`、Output `dist`、Node 24。`api/app.js` 為網站 API。

必要環境變數：

- `FIREBASE_SERVICE_ACCOUNT_JSON`：原 Firebase 專案服務帳戶 JSON，僅伺服器使用。
- `INITIAL_ADMIN_PASSWORD`：全新資料庫初始管理員密碼。
- `SESSION_SECRET`：簽署 Cookie 的長隨機字串。

Firestore 規則使用 `firestore.rules`，禁止瀏覽器直接讀寫。資料在 `dnweb/state` 單一文件，適合小型公會；接近單文件容量限制前需拆分集合及歷史分頁。請使用獨立測試資料庫驗證 Preview。

本機資料在 `.local/state.json`，僅支援單一伺服器程序；Vercel 未設定 Firebase 會回報錯誤。本機資料不會自動同步到正式站。既有 Discord 環境變數與端點保留供舊交易使用。

## 自訂數量項目

管理後台 → 數量項目，可新增／改名／刪除只有名稱的項目。角色卡可填各自數量（0–1,000,000,000,000 整數），按 Enter 或離開欄位儲存。只有角色本人及管理員可修改，數量不隨每週副本重置。刪除項目會同步清除所有角色對應數量。

## 管理員設定與無圖示職業清理

原管理員可在管理後台按「將 MrAirWolf 設為管理員」，只提升既有且啟用的帳號，不執行帳號刪除。若沒有可登入的管理員，由 Firebase 專案擁有者在 Firestore 的 `dnweb/state` 文件 `users` 陣列中找到 username 為 MrAirWolf 的項目，只把 `admin` 設為布林值 true（不是字串），保留 id、password、version 等其他欄位；重新整理網站即可。

本版第一次載入舊資料時移除無圖示職業，保留使用那些職業的角色並改成未設定職業。之後新增／編輯職業必須選有效圖示。

## 物品交流

獨立於舊交易結算的新刊登系統。所有登入成員可看物品名稱、圖片、文字說明及發布者，可搜尋、依刊登中／已結束篩選。本人及管理員可編輯、刪除或標記已結束，不涉及付款與分帳。

目前圖片使用 HTTPS 直連網址，資料庫只保存網址，不把圖片內容塞入單一 Firestore 文件。不能填 Google Drive 的分享網頁；圖片來源需允許網站載入。載入失敗會顯示提示。

後續若採用 Firebase Storage，需另開通 Storage bucket 與 Blaze 計費方案（Google One／Drive 會員不等於 Google Cloud 計費）。此版本沒有替使用者開通付費服務，也沒有宣稱已接通雲端圖片上傳。


## 活動日曆與統一提示

- 管理後台 → 活動管理 → 活動日曆：點選日期，可分別指定抽籤、快問快答與隨機事件；輸入任意標題片段即可搜尋，不分大小寫。
- 活動日為當日台灣時間 09:00 至隔日 09:00。指定內容優先於隨機及快問快答的開放分類，未指定則沿用隨機規則；修改日曆不重置已用次數。
- 籤文採穩定 ID、標題與內文；舊字串籤文自動轉成「冒險籤 N」標題並保留原文。題目重新排序不改變日曆引用，刪除有引用的內容前需先取消日曆安排。
- 儲存成功與錯誤以頂部綠框／紅框提示，約 3 秒收起；表單保留必要的欄位錯誤。
- 每次建置產生 version.json，已載入新版程式的瀏覽器每 60 秒檢查一次。偵測到不同部署時顯示右下角提醒，由使用者自行刷新；舊版尚無此檢查器，須先刷新一次。
